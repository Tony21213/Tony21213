## Ведомому

Цель: кнопка в шаге «Экспорт» — копия проекта exocad, где модели уже стоят в нашем артикуляторе
(шарнир на мыщелках пациента, вставки ССП, кости и движения на месте).

Сделать:
1. `Session.export_exocad_articulator(project_dir, out_dir=None, progress=None)`: проверка мыщелков
   (`articulation_condyles()`: `ready` и `applied`) → `case_from_session` → `export`.
   Проверка: `tests/test_exocad_articulator_export.py::test_session_and_api_contract` без xfail.
2. `POST /api/export/exocad-articulator` (`{"project": папка, "out": папка или null}`) — фоновая
   задача, ответ — сводка ядра; ошибки 400 с причиной (нет мыщелков, папка занята, нет проекта).
   Проверка: HTTP-тест.
3. Шаг «Экспорт»: кнопка «Для exocad с артикулятором»; спокойная подсказка, чего не хватает (папка
   проекта, готовые мыщелки, движения); результат по ролям, заметки (в том числе «мыщелки
   несимметричны…»), куда скопировать папку артикулятора; в инкогнито — без путей. Проверка: браузер
   на фантоме.
4. Тесты: HTTP «монтаж по точкам → выгрузка → файлы в папке»; отказ без готовых мыщелков; кейс без
   костей и черепа (вставки стандартные, заметка).
5. `docs/exocad.md`: порядок работы с копией проекта в exocad (тип антагониста, «Загрузить проект»,
   копирование папки артикулятора).
6. Реальный кейс по номеру вне репозитория; exe.

Можно менять: `app/session.py`, `app/server.py`, `app/web/app.js`, `app/web/style.css` (шаг «Экспорт»),
новые тесты, `docs/exocad.md` (раздел о выгрузке). Не трогать: `exocad_articulator_export.py`,
`exocad_facebow.py`, `mount_planes.py`, `exocad_webview.py`, `jawcase.py`.

## Контракт

Источник истины — `exocad_articulator_export`: `export`, `case_from_session`, `articulator_values`
(docstring) и `tests/test_exocad_articulator_export.py`; артикулятор — `exocad_facebow.write_articulator`.
Сверх кода:
- Сканы, маркер, кости — в координатах артикулятора exocad (x вправо пациента, y вперёд, z вверх,
  середина шарнира (30, −80, 60)); `.jawmotion` — в координатах регистратора.
- Папка артикулятора — под именем из `articulatormappings.xml` exocad (сейчас «Custom Case Designer»);
  в exocad её копирует пользователь, программа в папки exocad не пишет.
- exocad 3.3 (кейс 3, 12.10): к вставкам ССП обязательны парные вставки Беннетта (иначе копии вставок
  по кольцу при расчёте движения), `RotationAxis` = 0, вставки — открытые поверхности.
- Шарнир exocad горизонтален и симметричен; наклон оси пациента передаёт `.jawmotion` (к движениям
  добавляется открывание по Co_R–Co_L). Шарнир — центры головок (4 мм ниже Co).
- Ограничения: копия проекта не попадает в базу DentalDB («Загрузить проект»); вилка — Zebris SD из
  библиотеки exocad (свой маркер — Б.0.1).
- 13.10: при эстетической плоскости монтажа (лучше — «эстетическая через мыщелки») выгрузка сама пишет
  `<проект>.treatmentImages` и снимок-фон — в exocad кнопка «Вид Smile Design» (точный эстетический вид
  спереди); в результате — роль «эстетический вид» и заметка, показать их в шаге «Экспорт». Пример — кейс 4,
  копия `_CCD-2026-10-13-K4` на `Y:` (артикулятор «KStom кейс 4» в библиотеке exocad).
