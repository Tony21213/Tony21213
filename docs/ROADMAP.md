# crownai → уровень exocad AI Design: план

Проект некоммерческий: можно брать открытые нейросети, веса и наборы данных
с некоммерческими лицензиями. Данные пациентов (сканы, имена) остаются на
машине лаборатории. В git и в облако идут только код, обезличенные цифры
(профили, отчёты с хэшами) и картинки коронок.

## 1. Что такое «уровень exocad AI Design»

Публично известно ([exocad AI Design](https://exocad.com/our-products/ai-design),
[DentalCAD 3.3 Chemnitz](https://www.dental-tribune.com/news/exocad-launches-dentalcad-3-3-chemnitz/)):

- Предложение одиночной коронки обычно меньше чем за 2 минуты, считается в фоне.
- Форма подстраивается под анатомию пациента, соседние зубы и окклюзию, а затем
  доводится до отмеченной техником границы препарирования.
- Стиль задаётся одним из трёх способов:
  - техник выбирает библиотеку;
  - «по оставшимся зубам»;
  - AI выбирает стиль сам.
- В 3.3 есть до трёх соседних жевательных коронок и мосты до трёх единиц.

Архитектура exocad не публикуется. Судя по описанию, это гибрид: стиль из
библиотеки, нейросетевая адаптация к ситуации, затем обычная доводка
DentalCAD. К этой же схеме ведёт и наш проект.

### Измеримые цели

Проверяются на отложенных кейсах архива командой `crownai benchmark`.

| Показатель | Цель | Сейчас |
| --- | --- | --- |
| Кейсов, где коронка получена без ручной правки | ≥ 95% | ~50% в последней проверке (8 кейсов; исправление вырезки культи ещё не проверено на архиве) |
| Отклонение поверхности техника от коронки, медиана | ≤ 0,25 мм | 0,25–0,44 мм (правила с профилем, 3 кейса) |
| То же, 90-й перцентиль | ≤ 0,6 мм | ~1 мм |
| Контакт с соседями | 0–0,05 мм | ~0,05 мм |
| Помехи в движениях (Славичек) | 0 | 0–0,3 мм |
| Время на коронку | < 60 с | 60–160 с |
| Слепая оценка техниками (настоящая или наша) | ≥ 4 из 5 и «принял бы с мелкой правкой» в ≥ 80% | не проводилась |

## 2. Что уже есть

| Блок | Состояние |
| --- | --- |
| Импорт exocad (`.constructionInfo`: граница, ось, мезиальное направление, матрицы сканов), HTML-вьюер, папка-мост с наблюдением | работает |
| Вырезка культи, веер лучей, интальо с цементным зазором, выход из-под края, минимальная толщина, водонепроницаемый STL | работает; вырезка по границе исправлена, на архиве не проверена |
| Соседи и симметричный зуб | эвристики по карте высот и симметрии дуги — главный источник ошибок |
| Анатомия жевательных зубов | правила (бугры, валики, фиссуры), профиль, обученный на 406 коронках, библиотека ваших коронок (механика проверена: 0,1 мм на собственной коронке), выбор образца по соседям и месту до антагониста |
| Анатомия резцов и клыков | анатомическая модель, вписанная в симметричный зуб |
| Окклюзия | Славичек, траектории по рельефу зубов пациента, центрические контакты |
| Имплантаты и промежуточные части | одиночный зуб |
| Обучение | `tune-rules`, `build-library`, `check-library`, `benchmark` |

Чего нет: нейросетевого понимания скана (сегментация зубов, точки бугров и
контактов), нейросетевой генерации формы, мультиюнитов, интерфейса внутри
exocad. Всё считается на CPU в numpy, поэтому медленно.

## 3. Целевая архитектура

```
скан челюсти + антагонист + .constructionInfo
        │
 A. Понимание кейса (нейросети)  ─ сегментация зубов + номера FDI, точки бугров/контактов,
        │                           культя по границе exocad
 B. Предложение формы            ─ B1 библиотека: ваши коронки + естественные зубы Teeth3DS
        │                           B2 нейросеть: адаптация образца к соседям/антагонисту/границе
 C. Доводка (детерминированная)  ─ граница, контакты, окклюзия по Славичеку, толщины,
        │                           цементный зазор, проверка сетки   ← это у нас уже есть
 D. Выдача                       ─ STL в папку кейса exocad, варианты стиля, превью
        │
 E. Обучение по кругу            ─ каждая сданная работа → в библиотеку и в дообучение
```

## 5. Этапы

### Этап 0. Точка отсчёта (локальная сессия, 1–2 дня)

```
git pull
crownai build-library Y:\CAD-Data_2025 --out lab_library
crownai tune-rules Y:\CAD-Data_2025 --out profiles/rules_profile.json
crownai benchmark Y:\CAD-Data_2025 --n 40 --variants rules,profile,library ^
        --library lab_library --rules-profile profiles/rules_profile.json --out benchmark_report
```

Запушить `profiles/rules_profile.json` и `benchmark_report/` (summary.json,
results.jsonl, pictures/): там только хэши и картинки коронок. По отчёту
станет видно, где мы на самом деле: сколько кейсов падает и почему, и какой
способ ближе к технику по каждому типу зуба.

### Этап 1. Надёжность и скорость (CPU, без нейросетей)

- Разобрать отказы из отчёта по причинам: культя, граница, соседи, поверхность — и устранить их по одной.
- Перевести лучи и расстояния на Open3D. Цель: меньше 30 секунд на коронку вместе со Славичеком.
- Интальо и цементный зазор сделать смещением поверхности (manifold3d) вместо веера лучей. Тогда культи с поднутрениями и наклоном перестанут быть причиной отказа.
- **Готово, когда:** ≥ 90% кейсов архива проходят, время < 60 с.

### Этап 2. Понимание скана нейросетью

- Подключить сегментацию зубов: ToothGroupNetwork (лучший результат) или DentalModelSeg (чистая лицензия). Она заменит эвристики поиска соседей и симметричного зуба. Соседи, симметричный зуб и зубы-антагонисты станут точными сетками.
- Подключить точки бугров и контактов (ALI-IOS или модель с 3DTeethLand). Бугры новой коронки встанут по линии бугров соседей, контакты — по точкам контакта.
- Сегментированные зубы из ваших же сканов архива дадут тысячи естественных зубов ваших пациентов с их соседями и антагонистами.
- **Нужно:** PyTorch, видеокарта NVIDIA (желательно от 8 ГБ), Linux или WSL2 для CUDA-расширений.
- **Готово, когда:** соседи и симметричный зуб находятся в ≥ 98% кейсов, контакт по точкам.

### Этап 3. Данные для обучения

- **Архив лаборатории:** каждая коронка в системе координат зуба, вместе с её ситуацией (соседи, антагонист, граница). Инструменты уже есть (`build-library`), дополнить сегментированными соседями из этапа 2.
- **Teeth3DS+:** 24 000 естественных зубов с соседями и антагонистами.
  - Главный приём: убрать зуб из скана и учить сеть восстановить его по окружению. Это бесплатные десятки тысяч примеров «как выглядит зуб в этой ситуации», то же самое, что режим exocad «по оставшимся зубам».
  - Из тех же зубов — библиотека естественных зубов как дополнительные стили.
- **Bits2Bites:** проверка окклюзии и ориентации дуги на чужих данных.

### Этап 4. Нейросетевая адаптация формы (B2)

Схема по образцу DMC и MADCrowner, но с нашей доводкой на выходе:

1. **Вход:**
   - точки культи и границы;
   - мезиальный и дистальный соседи;
   - три ближайших зуба-антагониста;
   - образец из библиотеки, выбранный по ситуации.
2. **Выход:** смещение каждой точки образца. Деформация шаблона, а не форма с нуля, поэтому сетка всегда правильная, а живая анатомия образца сохраняется. Детали можно оживить диффузией (DuoDent).
3. **Предобучение:** на Teeth3DS+ (восстановление удалённого естественного зуба).
4. **Дообучение:** на ~900 коронках вашего архива (стиль ваших техников).
5. **Потери при обучении:**
   - расстояние до коронки техника;
   - проникание в соседей и антагонист;
   - гладкость деформации;
   - совпадение с границей.
6. **После сети:** всегда наш этап C — граница, контакты, Славичек, толщины.
7. **Обучение:** на локальной видеокарте или арендованной облачной. В облако — только обезличенная геометрия в системе координат зуба, без сканов челюстей; решение за лабораторией.
8. **Готово, когда:** в `benchmark` нейросеть не хуже библиотеки по каждому типу зуба, а медиана ≤ 0,25 мм.

### Этап 5. Охват

- Передние зубы: библиотека и обучение для позиций 1–3. Сейчас там только параметрическая модель.
- Две-три соседние коронки и мосты до трёх единиц, как в DentalCAD 3.3: совместная постановка с общими контактами.
- Имплантаты: канал под винт, профиль выхода под конкретную ти-базу.
- Стили: выбор библиотеки или техника, «по оставшимся зубам», «AI выбирает сам», перебор вариантов (`--library-variant` уже есть).

### Этап 6. Работа в лаборатории и обучение по кругу

- Наблюдение за папками exocad (`exocad-watch`): предложение готово за < 2 мин, превью, техник выбирает вариант.
- Каждая сданная работа автоматически уходит в библиотеку и в дообучение. Правки техника — самый ценный сигнал: что именно он поменял в нашем предложении.
- Слепая оценка: 30 пар «настоящая или наша», техники ставят оценки. Проводится на каждом крупном шаге.

## 6. Риски

| Риск | Что делаем |
| --- | --- |
| Данных меньше, чем у exocad | библиотека (живая анатомия без обучения), предобучение на Teeth3DS+, деформация шаблона вместо генерации с нуля (нужно меньше данных) |
| Нет видеокарты | этапы 0–1, 3 и библиотека работают на CPU; для этапов 2 и 4 — аренда облачной видеокарты только с обезличенной геометрией или покупка RTX 4060 Ti 16 ГБ и выше |
| Репозитории без лицензии (ToothGroupNetwork, DMC, CrossTooth, ToothForge) | только для исследований, в наш репозиторий не копировать, скачивать локально; где можно — брать Apache/MIT-альтернативы (DentalModelSeg, PoinTr, DuoDent) |
| Нет открытого API exocad | файловый обмен: папка кейса, `.constructionInfo` на входе, STL на выходе; позже — проверить импорт как пользовательской библиотеки зубов |
| Приватность | сканы и имена не покидают машину лаборатории; наружу только хэши, цифры, картинки коронок |

## 7. Ближайшие шаги

1. **Лаборатория (локальная сессия):** этап 0 (команды выше), push отчёта и профиля.
2. **Лаборатория:** ответить, какая видеокарта (модель и объём памяти) и какая ОС (Windows? есть ли WSL2?), допустимо ли обучение в облаке на обезличенной геометрии.
3. **Лаборатория:** скачать Teeth3DS+ с [OSF](https://osf.io/xctdy) (отсюда сайт недоступен), прочитать условия лицензии.
4. **Облачная сессия, параллельно:**
   - перевод лучей на Open3D (этап 1);
   - импорт Teeth3DS+ и библиотека естественных зубов (этап 3);
   - обёртка для ToothGroupNetwork и DentalModelSeg (этап 2), чтобы локальная сессия запустила её на своей видеокарте.
