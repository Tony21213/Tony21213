### Цель

Врач видит в шаге «Артикулятор», где программа поставила мыщелки и откуда она это
взяла, поправляет точку, если она не на месте, или подтверждает её. После этого
монтаж, шарнирная ось и синтетические движения строятся по проверенным точкам, а
автоматика их больше не трогает.

### Архитектурный контракт

**1. Приоритет точек.** На сторону хранится одна точка. Подтверждённая врачом
точка (поставлена вручную или принята) выше любой автоматической: автопоиск
ALI-CBCT, «Предложить» по сегментации и предложение перед монтажом её не
заменяют. Автоматическая точка — «проверьте», следующий автоматический поиск её
заменяет. Источники (`condyles.SOURCES`): `user` — врач, `ali-cbct` — нейросеть
ориентиров, `mandible` — по сетке нижней челюсти.

**2. Хранение.** Сессия: `Session.landmarks["Co_R" | "Co_L"]` (точка),
`Session.suggested` (ключ есть — не подтверждена), `Session.landmark_sources[key]`
(источник). Файл `.ccdcase`: `meta["landmarks"]`, `meta["suggested"]` (были) и
`meta["landmark_sources"]` (новое; необязательное). Кейс без
`landmark_sources` открывается: подтверждённая точка считается поставленной
врачом, предложенная — найденной по нижней челюсти. Новое КТ или закрытие КТ
сбрасывает точки, подтверждение и источники.

**3. Система координат.** Точки хранятся в миллиметрах пациента КТ (DICOM LPS:
x — влево, y — назад, z — вверх), нижняя челюсть — как на снимке. Это та же
точка, что «Мыщелок правый/левый» в ориентирах: верхушка головки нижней челюсти.
Окно «Артикулятор» и `JawCase` работают в координатах монтажа: мм КТ, верхняя
челюсть как на КТ, нижняя — в прикусе сканов, если он найден
(`Session.bite_motion`). Перевод — `condyles.to_view(p, bite_motion)` =
`bite_motion · p` (мыщелок едет с нижней челюстью), обратно — `from_view`; без
прикуса сканов обе системы совпадают.

**4. Применение.** `Session.articulation_mount(method)`:
- недостающие точки предлагаются по нижней челюсти (`_suggest_missing_condyles`,
  подтверждённые и найденные нейросетью не трогаются);
- точки готовы (`condyles.ready`: обе есть, проверок `error` нет) — монтаж по КТ
  с ними: шарнир — `to_view(p)` (`JawCase.mount(condyles=…)`), ССП по суставному
  бугорку — по черепу в соотношении КТ (`ct_condyles=p`, `exocad_webview.mount(…,
  eminence_condyles=…)`);
- не готовы — `auto` монтирует без КТ (по записи или средний артикулятор), `ct`
  — ошибка с причиной;
- шарнирная ось = ось через `condyle_right` и `condyle_left` монтажа
  (`Anatomy.points`); синтетические движения (`articulation_generate`) и экспорт
  лицевой дуги берут их оттуда;
- после поправки, подтверждения или сброса `state["applied"]` = false, пока
  интерфейс не вызовет монтаж (и затем генерацию движений) заново. Сервер сам не
  перемонтирует.

**5. API** (ошибки — 400 с `{"error": текст}`):

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| GET | `/api/articulation/condyles` | — | состояние |
| POST | `/api/articulation/condyles` | `{"side": "right"\|"left", "point": [x,y,z], "space": "ct"\|"view"}` | состояние |
| POST | `/api/articulation/condyles/confirm` | `{"side": "right"\|"left"\|"both"}` (по умолчанию both) | состояние |
| POST | `/api/articulation/condyles/reset` | `{"side": …}` (по умолчанию both) | состояние |

`space: "view"` — точка поставлена в окне «Артикулятор» (координаты монтажа),
`"ct"` — на срезах КТ. Поставить точку можно только при открытом КТ. Сброс —
к предложению по нижней челюсти (нейросеть заново не запускается); без
сегментации нижней челюсти после сброса точки нет.

**6. Состояние для интерфейса** (`condyles.state`, только JSON-типы):

```json
{
  "available": true,
  "bite": "scan",
  "points": {
    "right": {"key": "Co_R", "ct": [x, y, z], "view": [x, y, z], "source": "mandible",
              "source_label": "по нижней челюсти", "confirmed": false},
    "left":  {"key": "Co_L", "ct": null, "view": null, "source": null, "source_label": null, "confirmed": false}
  },
  "icd_mm": 98.4,
  "checks": [{"id": "icd", "level": "ok", "value": 98.4, "text": "межмыщелковое 98.4 мм"}],
  "ready": false,
  "confirmed": false,
  "applied": false,
  "segmentation": {"mandible": true, "skull": true}
}
```

`available` — открыт КТ; `bite` — `scan` (модели в прикусе сканов) или `ct`;
`ready` — монтаж по точкам возможен; `confirmed` — обе подтверждены; `applied`
— текущий монтаж сделан именно с этими точками. Маркеры в 3D ставятся по
`view`.

**7. Проверки** (`condyles.checks`, уровни `ok` / `warn` / `error` / `unknown`):

| id | Что | Пороги |
|---|---|---|
| `icd` | межмыщелковое расстояние | warn вне 80–125 мм, error вне 60–140 мм |
| `sides` | правый справа (в LPS x правого меньше) | перепутаны — error |
| `on_mandible_right`, `on_mandible_left` | точка на поверхности нижней челюсти КТ | warn > 1.5 мм, error > 5 мм; нет сегментации — unknown |
| `asymmetry` | разница правого и левого по высоте и глубине в системе монтажа | warn > 5 мм |

С `error` монтаж по точкам не идёт. `unknown` монтаж не блокирует.

**8. Отсутствующая или неполная сегментация.** Нет КТ — `available: false`,
монтаж без КТ. КТ есть, нижней челюсти нет — автоматических точек нет, врач
ставит их вручную (`set_condyle`), проверки «на нижней челюсти» — `unknown`,
монтаж по КТ идёт по поставленным точкам. Найден один мыщелок (поле КТ обрезано) —
второй ставит врач; пока его нет, монтаж без КТ. Нет черепа — ССП по умолчанию,
как раньше. Зеркальная подстановка недостающего мыщелка не делается.

1. `tests/test_condyles_contract.py` проходит целиком; xfail ведомого сняты (тесты

2. В шаге «Артикулятор» видны обе точки: источник, подтверждена ли, межмыщелковое,
   проверки с уровнями. Точку можно сдвинуть, подтвердить, сбросить; работает
   инкогнито; интерфейс спокойный, без лишних кнопок.
3. Поправки сохраняются в `.ccdcase` и восстанавливаются при открытии; прежние кейсы
   открываются.
4. Монтаж идёт по точкам врача: в прикусе сканов шарнир = `bite_motion · Co`, ССП —
   в соотношении КТ; межмыщелковое в состоянии равно межмыщелковому монтажа; после
   поправки `applied: false`, после перемонтажа и генерации траектории начинаются от
   новых точек.
5. Автопоиск (ALI-CBCT, «Предложить», предложение перед монтажом) не меняет
   подтверждённые точки — есть тест.
6. Ошибка проверки блокирует монтаж по КТ с понятной причиной; без сегментации нижней
   челюсти точки ставятся вручную.
7. Проверено на обезличенных реальных кейсах вне репозитория (кейсы №1 и №2): в
   передаче — числа без имён (сдвиг шарнира в прикусе сканов против прежнего монтажа,

### Известные ограничения

- Co — верхушка головки; шарнир, как и раньше, проходит через верхушки, а не через
  кинематический центр головки (≈4 мм ниже, `guidance.CONDYLE_RADIUS_MM`). Это
  отдельная задача ведущего.
- Сброс возвращает предложение по нижней челюсти; повторный поиск ALI-CBCT — только
  кнопкой автопоиска ориентиров.
- Поправки мыщелков — уровень сессии: отмена `JawCase.undo` их не возвращает.
- Команда `facebow` (командная строка) по-прежнему ищет мыщелки по кости сама; точки
  кейса берёт только монтаж в приложении.
- `Session.suggest_landmarks` ищет мыщелки без направления «вперёд» (в отличие от
  `_suggest_missing_condyles`); выравнивать — в задаче 1 или отдельно.
- В `docs/exocad.md` (раздел «Вставки ССП») строка про `OFF BINARY` разорвана
  переводом строки — исправить при следующей правке этого файла.

### Уточнение по итогам приёмки: поверхность КТ без сегментации

По запросу владельца для ручной поправки без `mandible` используется пороговая
кость `GET /api/ct/surface?part=bone` (без параметра остаются зубы). Она не
переводится в прикус сканов: щелчок передаёт `space: "ct"`, а на время поправки
маркеры берутся из `ct`. После выхода маркеры снова соответствуют показанному
прикусу. Для сегментированной нижней челюсти в прикусе сканов используется `view`;
при выключенном «Прикусе» — `ct`. Хранение, приоритет и применение не изменены.
В `articulation/guides` добавлено `ct_axes`: оси монтажа, повёрнутые обратно в КТ
без переноса. Стрелки используют оси и координаты показанного маркера.
