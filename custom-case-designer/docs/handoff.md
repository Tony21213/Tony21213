### Цель

Врач видит в шаге «Артикулятор», где программа поставила мыщелки и откуда она это
взяла, поправляет точку, если она не на месте, или подтверждает её. После этого
монтаж, шарнирная ось и синтетические движения строятся по проверенным точкам, а
автоматика их больше не трогает.

### Архитектурный контракт

**1. Приоритет точек.** На сторону хранится одна точка. Подтверждённая врачом
точка (поставлена вручную или принята) выше любой автоматической: автопоиск
ALI-CBCT, «Предложить» по сегментации и предложение перед монтажом её не
заменяют. Автоматическая точка — «проверьте», следующий автоматический поиск её
заменяет. Источники (`condyles.SOURCES`): `user` — врач, `ali-cbct` — нейросеть
ориентиров, `mandible` — по сетке нижней челюсти.

**2. Хранение.** Сессия: `Session.landmarks["Co_R" | "Co_L"]` (точка),
`Session.suggested` (ключ есть — не подтверждена), `Session.landmark_sources[key]`
(источник). Файл `.ccdcase`: `meta["landmarks"]`, `meta["suggested"]` (были) и
`meta["landmark_sources"]` (новое; необязательное). Кейс без
`landmark_sources` открывается: подтверждённая точка считается поставленной
врачом, предложенная — найденной по нижней челюсти. Новое КТ или закрытие КТ
сбрасывает точки, подтверждение и источники.

**3. Система координат.** Точки хранятся в миллиметрах пациента КТ (DICOM LPS:
x — влево, y — назад, z — вверх), нижняя челюсть — как на снимке. Это та же
точка, что «Мыщелок правый/левый» в ориентирах: верхушка головки нижней челюсти.
Окно «Артикулятор» и `JawCase` работают в координатах монтажа: мм КТ, верхняя
челюсть как на КТ, нижняя — в прикусе сканов, если он найден
(`Session.bite_motion`). Перевод — `condyles.to_view(p, bite_motion)` =
`bite_motion · p` (мыщелок едет с нижней челюстью), обратно — `from_view`; без
прикуса сканов обе системы совпадают.

**4. Применение.** `Session.articulation_mount(method)`:
- недостающие точки предлагаются по нижней челюсти (`_suggest_missing_condyles`,
  подтверждённые и найденные нейросетью не трогаются);
- точки готовы (`condyles.ready`: обе есть, проверок `error` нет) — монтаж по КТ
  с ними: шарнир — центр головки под `to_view(p)` (с 12.10.2026 — на 4 мм ниже
  по вертикали монтажа; `JawCase.mount(condyles=…)` получает Co), ССП по суставному
  бугорку — по черепу в соотношении КТ (`ct_condyles=p`, `exocad_webview.mount(…,
  eminence_condyles=…)`);
- не готовы — `auto` монтирует без КТ (по записи или средний артикулятор), `ct`
  — ошибка с причиной;
- шарнирная ось = ось через `condyle_right` и `condyle_left` монтажа
  (`Anatomy.points`); синтетические движения (`articulation_generate`) и экспорт
  лицевой дуги берут их оттуда;
- после поправки, подтверждения или сброса `state["applied"]` = false, пока
  интерфейс не вызовет монтаж (и затем генерацию движений) заново. Сервер сам не
  перемонтирует.

**5. API** (ошибки — 400 с `{"error": текст}`):

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| GET | `/api/articulation/condyles` | — | состояние |
| POST | `/api/articulation/condyles` | `{"side": "right"\|"left", "point": [x,y,z], "space": "ct"\|"view"}` | состояние |
| POST | `/api/articulation/condyles/confirm` | `{"side": "right"\|"left"\|"both"}` (по умолчанию both) | состояние |
| POST | `/api/articulation/condyles/reset` | `{"side": …}` (по умолчанию both) | состояние |

`space: "view"` — точка поставлена в окне «Артикулятор» (координаты монтажа),
`"ct"` — на срезах КТ. Поставить точку можно только при открытом КТ. Сброс —
к предложению по нижней челюсти (нейросеть заново не запускается); без
сегментации нижней челюсти после сброса точки нет.

**6. Состояние для интерфейса** (`condyles.state`, только JSON-типы):

```json
{
  "available": true,
  "bite": "scan",
  "points": {
    "right": {"key": "Co_R", "ct": [x, y, z], "view": [x, y, z], "source": "mandible",
              "source_label": "по нижней челюсти", "confirmed": false},
    "left":  {"key": "Co_L", "ct": null, "view": null, "source": null, "source_label": null, "confirmed": false}
  },
  "icd_mm": 98.4,
  "checks": [{"id": "icd", "level": "ok", "value": 98.4, "text": "межмыщелковое 98.4 мм"}],
  "ready": false,
  "confirmed": false,
  "applied": false,
  "segmentation": {"mandible": true, "skull": true}
}
```

`available` — открыт КТ; `bite` — `scan` (модели в прикусе сканов) или `ct`;
`ready` — монтаж по точкам возможен; `confirmed` — обе подтверждены; `applied`
— текущий монтаж сделан именно с этими точками. Маркеры в 3D ставятся по
`view`.

**7. Проверки** (`condyles.checks`, уровни `ok` / `warn` / `error` / `unknown`):

| id | Что | Пороги |
|---|---|---|
| `icd` | межмыщелковое расстояние | warn вне 80–125 мм, error вне 60–140 мм |
| `sides` | правый справа (в LPS x правого меньше) | перепутаны — error |
| `on_mandible_right`, `on_mandible_left` | точка на поверхности нижней челюсти КТ | warn > 1.5 мм, error > 5 мм; нет сегментации — unknown |
| `asymmetry` | разница правого и левого по высоте и глубине в системе монтажа | warn > 5 мм |

С `error` монтаж по точкам не идёт. `unknown` монтаж не блокирует.

**8. Отсутствующая или неполная сегментация.** Нет КТ — `available: false`,
монтаж без КТ. КТ есть, нижней челюсти нет — автоматических точек нет, врач
ставит их вручную (`set_condyle`), проверки «на нижней челюсти» — `unknown`,
монтаж по КТ идёт по поставленным точкам. Найден один мыщелок (поле КТ обрезано) —
второй ставит врач; пока его нет, монтаж без КТ. Нет черепа — ССП по умолчанию,
как раньше. Зеркальная подстановка недостающего мыщелка не делается.

2. В шаге «Артикулятор» видны обе точки: источник, подтверждена ли, межмыщелковое,

   инкогнито; интерфейс спокойный, без лишних кнопок.
3. Поправки сохраняются в `.ccdcase` и восстанавливаются при открытии; прежние кейсы
   открываются.
4. Монтаж идёт по точкам врача: в прикусе сканов шарнир = `bite_motion · Co`, ССП —
   в соотношении КТ; межмыщелковое в состоянии равно межмыщелковому монтажа; после
   поправки `applied: false`, после перемонтажа и генерации траектории начинаются от
   новых точек.
5. Автопоиск (ALI-CBCT, «Предложить», предложение перед монтажом) не меняет
   подтверждённые точки — есть тест.
6. Ошибка проверки блокирует монтаж по КТ с понятной причиной; без сегментации нижней
   челюсти точки ставятся вручную.
7. Проверено на обезличенных реальных кейсах вне репозитория (кейсы №1 и №2): в
   передаче — числа без имён (сдвиг шарнира в прикусе сканов против прежнего монтажа,

### Уточнение по итогам приёмки: поверхность КТ без сегментации

По запросу владельца для ручной поправки без `mandible` используется пороговая
кость `GET /api/ct/surface?part=bone` (без параметра остаются зубы). Она не
переводится в прикус сканов: щелчок передаёт `space: "ct"`, а на время поправки
маркеры берутся из `ct`. После выхода маркеры снова соответствуют показанному
прикусу. Для сегментированной нижней челюсти в прикусе сканов используется `view`;
при выключенном «Прикусе» — `ct`. Хранение, приоритет и применение не изменены.
В `articulation/guides` добавлено `ct_axes`: оси монтажа, повёрнутые обратно в КТ
без переноса. Стрелки используют оси и координаты показанного маркера.

### Архитектурный контракт

- **Плоскости** — `mount_planes.PLANES` (ключ → название и точки):
  - `occlusal` — по сканам, ориентиры не нужны (как было; по умолчанию);
  - `frankfurt` — Po_R, Po_L, орбиталь (Or_R/Or_L, хватает одной);
  - `axis_orbital` — шарнирные точки Co_R, Co_L и орбиталь. «Вправо» — линия
    мыщелков: шарнир артикулятора проходит через оба мыщелка даже при разной их
    высоте, модели наклоняются вместе с осью пациента;
  - `camper` — Tr_R, Tr_L, Al_R+Al_L (мягкие ткани, ставит врач);
  - `hip` — HN_R, HN_L, IP (ставит врач).
  Po, Or, Co находит ALI-CBCT; Tr, Al, HN — только вручную (шаг «КТ»).
- **Оси монтажа** — `mount_planes.rotation(kind, up, anterior, landmarks, condyles)`:
  строки «вправо, вперёд, вверх» в координатах кейса. «Вверх» — нормаль
  плоскости в сторону окклюзионного «вверх»; «вперёд» — направление дуги,
  спроецированное в плоскость (рыскание моделей как у окклюзионной); у
  оси-орбитальной «вправо» — Co_L → Co_R. Точки черепа — мм КТ (они неподвижны
  с верхней челюстью), мыщелки — в прикусе монтажа (шарнир).
- **Монтаж** — `exocad_webview.mount(..., plane="occlusal", landmarks=None)` и
  `JawCase.mount(method, ..., plane="occlusal", landmarks=None)`. Плоскость
  выбирается только для монтажа по КТ (иначе `ValueError`). Нет точек —
  `ValueError` с их названиями. ССП по бугорку считается в системе монтажа, то
  есть от выбранной плоскости; Беннетт — по Ханау от этого ССП.
- **Шарнир** — центры головок мыщелков: на радиус головки
  (`guidance.CONDYLE_RADIUS_MM`, 4 мм) ниже точек Co по «вверх» монтажа (у
  оси-орбитальной плоскость строится через эти центры). Вокруг них вращается
  челюсть, на них головки артикулятора exocad; путь мыщелка по бугорку — путь
  этого же центра, профиль бугорка — от Co. Точки врача, проверки, маркеры — Co.
- **Состояние** — `JawCase.plane` (ключ); `state()["mounting"]["plane"] =
  {"key", "name"}`; отмена и файл кейса (`.npz` JawCase) хранят выбор; старые
  файлы — `occlusal`. Эстетический монтаж ставит `plane = "aesthetic"`.
- **Наклон к окклюзионной** — `mount_planes.relative_angles(R, up, anterior)`:
  `pitch_deg` (передом вверх +), `roll_deg` (правая сторона ниже +); при
  неокклюзионной плоскости — заметка монтажа «плоскость монтажа к окклюзионной:
  передом вверх на …°, крен …°».
- **Доступность** — `mount_planes.available(landmarks, condyles)`: для каждой
  плоскости название, `available`, `missing` (названия точек).

    `articulator/<папка>` — под тем именем, на которое наш тип указывает в
    `articulatormappings.xml` exocad (сейчас «Custom Case Designer»):
    межмыщелковое и углы пациента, вставки ССП **и парные вставки Беннетта**
    (без них exocad при расчёте движения рисует копии вставок по кольцу),
    скрытый `RotationAxis` = 0, плоскость гипсовки. Проверено в exocad 3.3 на
    кейсе 3 (12.10.2026), подробности — `docs/exocad.md`.
  - к построенным движениям добавляется открывание вокруг настоящей оси
    Co_R–Co_L: шарнир exocad всегда горизонтален, наклон оси пациента передаёт
    только файл движений. Если мыщелки стоят к горизонтали монтажа на разной
    высоте, в заметках — «мыщелки несимметричны…» (`off_axis_mm`).
  `.scanInfo`, `.matrix4` и моделировки исходного проекта не копируются.
  Непустую папку назначения выгрузка не перезаписывает (`FileExistsError`).
- **Углы артикулятора** — `articulator_values(anatomy, settings)`: от горизонтали
  монтажа. Если у настроек своя горизонталь (`Settings.frame`), направления
  путей переводятся (`kinematics._to_mount`).
- **Вход из сессии** — `case_from_session(session)`, после
  `Session.articulation_mount`:
  - сканы — из исходных файлов с цветом;
  - нижняя челюсть и её кость — `lower_fix · bite_motion · reg.transform`;
  - пути мыщелков — по черепу КТ у точек Co кейса (`condyles.resolve`);
  - движения — из `jaw.movements`.
- **Сводка** — только JSON-типы, без имён пациентов: файлы по ролям, тип
  антагониста, заметки, межмыщелковое, углы, плоскость, мыщелки в
  артикуляторе, матрица «кейс → артикулятор».
- **Готовность.** Выгрузка из приложения — только при готовых мыщелках
  (`condyles.ready`, `applied`) и монтаже по ним. Ядро при монтаже не по КТ
  выгружает, но пишет заметку.
- **Команда** `python -m casedesigner exocad-articulator КЕЙС.ccdcase ПРОЕКТ
  [-o ПАПКА] [--ct КТ] [--exocad DentalCADApp] [--travel 6] [--no-movements]`.

### Критерии приёмки

1. `tests/test_exocad_articulator_export.py` проходит целиком, xfail снят.
2. В шаге «Экспорт» есть кнопка «Для exocad с артикулятором». Она доступна, если
   выбрана папка проекта exocad, модели смонтированы по готовым мыщелкам и
   движения построены; иначе — спокойная подсказка, чего не хватает. Результат
   показывается по ролям, с заметками и подсказкой, куда скопировать папку
   артикулятора; в инкогнито путей нет.
3. API: `POST /api/export/exocad-articulator` (`{"project": папка, "out": папка
   или null}`) — фоновая задача; ответ — сводка ядра. Ошибки — 400 с причиной
   (нет мыщелков, папка занята, нет проекта).
4. Копия проекта открывается в exocad 3.3 («Загрузить проект»). Маркер
   совмещается сам, вилка — по одной точке. Модели стоят в артикуляторе, кости
   двигаются с челюстями, открывание идёт вниз. Проверяет пользователь (группа
   В); ведомый готовит копию и описание.
5. Проверено на обезличенном кейсе вне репозитория: числа без имён в обратной
   передаче. Сравнить с проектом, собранным скриптами (`_CCD-2026-10-07`):
   положения моделей ≤ 0,5 мм.
6. Собран exe; `git diff --check` чистый; данных пациентов в Git нет.

### Задачи ведомого

1. **Сессия:** `Session.export_exocad_articulator(project_dir, out_dir=None,
   progress=None)`. Проверяет готовность мыщелков (`articulation_condyles()`:
   `ready` и `applied`), собирает вход (`case_from_session`), выгружает ядром.
   Снять xfail с `test_session_and_api_contract`.
2. **API:** маршрут `export/exocad-articulator` — фоновая задача, как остальные
   долгие операции.
3. **Интерфейс:** кнопка в шаге «Экспорт», состояние готовности и подсказки,
   результат по ролям, заметки, инкогнито.
4. **Документация:** раздел в `docs/exocad.md`: порядок работы в exocad с копией
   проекта (тип антагониста, «Загрузить проект», копирование папки артикулятора).
5. **Тесты:**
   - HTTP-цепочка на фантоме: монтаж по точкам → выгрузка → файлы в папке;
   - отказ без готовых мыщелков;

   собрать exe.

### Известные ограничения

- Копия проекта не попадает в базу DentalDB: её открывают в CAD через
  «Загрузить проект».
- Папку артикулятора в `library\articulator` exocad копирует пользователь.
  Программа в файлы exocad не пишет.
- Шарнир артикулятора exocad горизонтален и симметричен (одна сетка головки,
  одно межмыщелковое; `RotationAxisLeft/Right` головки не двигает): при разной
  высоте мыщелков головки отходят от них (кейс 3 — на ±3,2 мм). Решение
  владельца: череп и модели ровно, движение по настоящей оси — в файле движений.
  Выбор плоскости монтажа — отдельная задача ведущего (ветка `lead/mount-plane`).
- Вилка в маркере — Zebris SD из библиотеки exocad. Свой несимметричный маркер —
  следующий каркас (дорожная карта, Б.0.1).
- Записанные движения идут в файл движений, как построенные. Частота — по
  времени записи; без времени — 60 кадров в секунду.
- Команда `exocad-articulator` открывает кейс с КТ. Если КТ перенесли, нужен
  `--ct`.
