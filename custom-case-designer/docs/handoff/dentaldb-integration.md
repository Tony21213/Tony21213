# DentalDB 3.3 SR1: сборка в текущий заказ

Исполнитель: Codex · Ветка: follower/dentaldb-integration · База: `0af4d67`.
Задача владельца 10.11.2026: реализовать предложенную интеграцию под установленный SR1.
Ветка включает зависимость `follower/condyle-distraction` до `b4169e0`, чтобы сборка не теряла дистракцию.

## Контракт реализации

- Основной маршрут: сохранённый заказ DentalDB → `--dental-project` → KStom → сборка в этот же заказ → DentalCAD SR1.
- Точный файл проекта, роли сканов и матрицы; имена пациентов не выводятся в диагностике, контекст в окне — номер.
- Существующий экспорт копии сохраняется. Готовая моделировка требует Duplicate в DentalDB.
- Промежуточная сборка, контроль ревизий, резервные копии, журнал замены и восстановление; чужие файлы не затираются.
- Локальный `.ccdcase` и состояние монтажа позволяют продолжить подготовку, не применяя матрицы повторно.
- Кнопка DentalDB добавляется в установленный SR1 с резервной копией и откатом. Исполняемые файлы exocad не меняются.
- Новый заказ с назначениями из KStom и универсальный автоимпорт новых заказов — отдельный этап; заказ создаётся в DentalDB.

Можно менять: новые `casedesigner/dentaldb*.py`, `app/steps/dentaldb.py`, `web/steps/dentaldb.js`, `tools/install_dentaldb.py`,
`tests/test_dentaldb*.py`; точки подключения в `app/main.py`, `server.py`, `steps/casefile.py`, `web/app.js`, `web/core.js`,
`web/steps/export.js`, при необходимости `exocad_project.py`, упаковка, README и docs/exocad.md.
Это выделение границ по прямому поручению владельца, без правок доски и карты ведущего.

## Обратная передача

В работе. Карте: интеграция сохранённого заказа DentalDB SR1 → KStom → публикация файлов → DentalCAD.
