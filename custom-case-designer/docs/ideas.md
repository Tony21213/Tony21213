# Входящие владельца

Сюда админский терминал (облачная сессия владельца) записывает мысли и
решения владельца по проекту — с датой, как сказано. Код админский терминал не
меняет и в чужие ветки не пишет: он ведёт этот файл и, по решению владельца,
правила работы (`WORK_SPLIT.md`, `CLAUDE.md`, `AGENTS.md`), когда их не
меняют другие ветки, — поэтому
правки дорожной карты в ветках ведущего с ним не конфликтуют.

Ведущий при каждой передаче:
- разбирает новые записи в `docs/roadmap.md` (раздел «Что должно получиться» и
  очередь) — по правилам `CLAUDE.md`;
- отмечает у записи «→ в карте: <пункт>» или «вопрос владельцу: …».

Статусы: **новое** · **в карте** · **вопрос** · **отложено** · **отклонено (с согласия владельца)**.

### 12.10.2026 — кнопка «Исправить прикус» — сразу после совмещения сканов с КТ, до монтажа
- **Статус:** новое, решение владельца (уточнено им же: сначала было записано
  «в шаге „Артикулятор“, после плоскости монтажа»).
- **Где в программе — в шаге «Сканы»**, после совмещения сканов с КТ и прикуса
  сканов, до монтажа. Причина (владелец): исправление сдвигает нижнюю челюсть,
  а с ней мыщелки — шарнир в прикусе сканов едет с нижней челюстью. Если
  исправить после монтажа, шарнир артикулятора останется на старых местах
  мыщелков.
- **Порядок:** КТ → сканы на КТ → прикус сканов → исправление прикуса →
  плоскость монтажа и шарнир по мыщелкам в исправленном прикусе → движения →
  экспорт.
- **Мыщелки для `bite.correct_bite`** — Co_R/Co_L из шага «КТ» (поставленные
  врачом или найденные автоматически и проверенные); с ними ограничение
  строже: вверх ≤ 0,1 мм. Без КТ — треугольник Бонвилля.
- **Что показать врачу:** отчёт, в том числе на сколько сдвинулся каждый
  мыщелок; предупреждения; карту контактов до и после; кнопки «принять» и
  «отменить».
- **Защита порядка** (предложение админского терминала, контракт — за
  ведущим):
  - если прикус меняют на уже смонтированном кейсе (исправили, отменили,
    исправили заново), монтаж и движения пересчитываются, как сейчас после
    поправки мыщелков («Перемонтировать»);
  - выгрузка для exocad, сделанная до этого, помечается устаревшей;
  - если врач потом в шаге «Артикулятор» заметно поправил мыщелки
    (порог — за ведущим), программа предлагает исправить прикус заново.
- **В очереди пары** — по-прежнему после плоскости монтажа: файлы сессии,
  сервера и интерфейса заняты выгрузкой для exocad, а каркас плоскости монтажа
  уже готов. Благодаря защите порядка очередность реализации на результат не

- **Статус:** новое, задача ведущему (владелец одобрил). Ставить после выбора

- **Зачем.** Сейчас (`guidance.condylar_path`) путь считается в одном

- **Как (предложение админского терминала, контракт — за ведущим):**
  1. Поверхности из КТ: головка мыщелка — сетка нижней челюсти над шейкой
     вокруг подтверждённой Co; суставная поверхность височной кости (задняя
     стенка, крыша ямки, скат бугорка, внутренняя стенка ямки) — по яркости
     КТ в области сустава, не только по сегментации (тонкая крыша ямки).
  2. Диск — прослойка: поверхность кости сдвигается на его толщину; два
     варианта — постоянная (щель в покое, как сейчас) и анатомическая (толще
     сзади, тонкая средняя часть по скату); врачу — оба пути и разница в
     градусах.
  3. Скольжение: на каждом шаге протрузии и латеротрузии мыщелок прижимается
     вверх (и внутрь на балансирующей стороне) к поверхности с диском без

  4. Путь центра мыщелка в 3D → тот же подбор, что для записей

     exocad.
