# Параллельная работа

Этот файл задаёт границы для двух параллельных веток. Общая ветка
интеграции — `claude/lucid-euler-8zyldi`; каждый участник работает в своей ветке и
отдельном worktree.

## Поток 1: ядро и сборка

- `casedesigner/fusion.py`, `jawcase.py`, `kinematics.py`, `motion.py`,
  `landmarks.py`, `aesthetic.py`, `bite.py`, `register.py`;
- API и состояние: `casedesigner/app/session.py`, `server.py`;
- тесты ядра, PyInstaller, финальная интеграция и сборка exe;
- `docs/roadmap.md` как единый список функций.

## Поток 2: интерфейс и exocad

- `casedesigner/app/web/`;
- проверка сценариев в exocad только через официальные форматы;
- `docs/exocad.md`, инструкции по ручной проверке;
- собственный несимметричный скан-маркер и визуальная проверка артикулятора.

Если для задачи потока 2 нужно изменить Python API, он сначала описывает контракт в
`docs/handoff.md`. Поток 1 вносит API, после чего поток 2 подключает интерфейс.

## Правила слияния

1. Перед началом: `git fetch origin`, новая ветка от актуальной
   `origin/claude/lucid-euler-8zyldi`.
2. Один файл в один момент меняет только один поток.
3. Коммит решает одну задачу. В тексте коммита и коде нет идентификаторов
   инструментов и авторов автоматизации.
4. Новая функция в том же коммите записывается в `docs/roadmap.md`; изменения
   форматов exocad — ещё и в `docs/exocad.md`.
5. Перед передачей: целевые тесты, `git diff --check`, номер коммита и краткая
   запись в `docs/handoff.md`.
6. Интегратор переносит готовый коммит через `git cherry-pick`; force-push не используется.
7. Реальные КТ, сканы, выгрузки и имена пациентов не попадают в Git, логи и
   сообщения. Кейсы обозначаются только номерами.
8. PR не создаётся без отдельной просьбы владельца.
