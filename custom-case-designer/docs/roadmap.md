# Дорожная карта

Собрано по всем вашим запросам за проект. Сначала очередь работ: что можно
сделать в облачной сессии, затем что требует локальной сессии на ПК, затем
что ждёт ваших данных или доступа к exocad. Ниже — принципы, полное описание
того, что должно получиться, состояние, отложенное и открытые вопросы.

Карта ведётся по ходу работы (правила в `CLAUDE.md`):
- каждая новая функция сразу записывается сюда;
- при каждой новой идее и каждом сделанном пункте очередь пересортировывается;
- сделанное уходит из очереди в таблицу «Где мы сейчас».

## Очередь работ

### А. Можно сделать в облачной сессии
По порядку приоритета.

1. **Журнал ошибок** в файл, без имён пациентов. Маленькая задача, но без
   неё трудно разбирать сбои при первых запусках на ПК.
2. **Исправление прикуса, как в Bite-Finder (ядро).** Поиск по шести
   степеням свободы, прикус без скана прикуса, проверка по мыщелкам на КТ,
   отчёт: сдвиг в мм и градусах, контакты по зубам до и после. Проверка
   точности на пяти выгрузках exocad, которые есть в этой сессии: верный
   прикус сбивается на известную величину, программа должна его вернуть.
3. **Шаг «Прикус» в программе.** Кнопка исправления, отчёт, карта контактов,
   принять или отменить. Здесь же отдельный выбор режима прикуса (нижняя
   челюсть за сканом или статичное наложение на КТ).
4. **Сканы гипсовых моделей в программе** — проверить весь путь от загрузки
   до экспорта.
5. **Шаг «Ориентиры» в программе.** Точки на срезах, подсказки мыщелков и
   порионов, плоскости Франкфурта, HIP и Кампера, экспорт в системе плоскости.
6. **Автоматические ориентиры на КТ (ALI-CBCT).** Веса скачиваются отсюда.
   Нужные точки: порионы, орбитали, мыщелки с внутренним и наружным
   полюсом, ANS, PNS, N, S, Ba, резцовое отверстие — около 16 точек по
   ~117 МБ. Перевести в ONNX, проверить на открытых КТ, загрузка в
   программе по кнопке, как модели сегментации. Подсказки на шаге
   «Ориентиры» станут автоматическими; затем анализы (Steiner, Ricketts).
7. **Расхождение стандартного артикулятора с осью пациента (ядро).** На
   сколько мм по резцам и молярам расходится движение при эстетическом
   монтаже. Отсюда видно, когда нужен свой артикулятор для exocad.
8. **Шаг «Артикулятор» в программе.** Монтаж с галочкой «По эстетической
   плоскости», динамика по мыщелкам пациента, генерация движений, анимация,
   карта контактов, FGP в STL.
9. **Импорт записей движений в программе** (P-ART и другие системы) —
   на синтетических файлах; точное чтение — когда будут образцы (группа В).
10. **Эстетика в программе.** Фото анфас, точки на фото и скане, горизонт и
    средняя линия, экспорт в эстетической системе, расхождение с
    функциональной.
11. **Скан лица (ядро).** Статичное совмещение скана лица с кожей на КТ —
    на синтетических данных.
12. **Заготовки для Windows:** сегментация на видеокарте (ONNX Runtime
    DirectML, с откатом на процессор) и скрипт установщика. Пишутся здесь,
    проверяются в локальной сессии.

### Б. Нужна локальная сессия на ПК с Windows
1. **Релиз моделей `models-v1`.** Модели готовы и проверены по контрольным
   суммам, но выложить релиз на GitHub из облака нельзя: `gh release create`.
2. **Первый билд 0.1:** сборка exe и проверка на Windows — окно программы,
   скачивание моделей, пути с кириллицей, архивы 7z и rar.
3. **Реальные кейсы:** 2–3 кейса от КТ до открытия в exocad, затем 10–20 из
   архива: сравнение с exoplan и с ручной посадкой, разбор неудач.
4. **Исправление прикуса на кейсах из архива.**
5. **Видеокарта и установщик** — проверка заготовок из пункта А.12.
6. **Зубы и точки на сканах (ToothInstanceNet, решение 3DTeethLand).** Код
   под MIT, веса на Google Drive, который из облака закрыт. Скачать в
   локальной сессии и проверить, работает ли без видеокарты NVIDIA (модели
   нужны свои ядра CUDA). Даёт номера зубов и точки бугров, режущих краёв,
   контактов на сканах: пригодится для исправления прикуса, контактов по
   зубам и окклюзионной плоскости.
7. **DentalSegmentator** (CC BY 4.0, Zenodo из облака закрыт): скачать и
   сравнить с нынешними моделями сегментации на реальных КТ.
6. Найденные ошибки и неудачи возвращаются в группу А.

### В. Нужны ваши данные или доступ к exocad
- **Образец `.jawMotion`**, который exocad уже открывал → выгрузка движения
  в exocad (Jaw Motion Import).
- **Выгрузки P-ART, Zebris, Modjaw, CADIAX** (или вывод `--inspect`) →
  точное чтение записей, сравнение генерации с настоящими движениями.
- **Доступ к exocad:**
  - как устроены виртуальное пространство и артикуляторы;
  - свой артикулятор для exocad: эстетический монтаж, шарнир каждого
    мыщелка на мыщелке пациента по трём плоскостям, суставные пути пациента —
    если exocad официально позволяет добавлять свои артикуляторы;
  - имена объектов и файлов для автозагрузки, монтаж в артикулятор exocad.
- **Модель в артикуляторе exocad + КТ того же пациента**, по одной на
  артикулятор → калибровка всех артикуляторов, включая Gamma.
- **3D-сканы лица**, в том числе с выражениями → проверка совмещения с КТ.
- **Веса SegmentAnyTooth** выдаются по подписанному соглашению, которое
  отправляется авторам по почте. Модель находит зубы на внутриротовых фото;
  на фото с улыбкой может помочь автоматически ставить точки для эстетики.
  Приоритет низкий.
- **Накопленные поправки пользователей** → дообучение моделей совмещения и
  сегментации.
- **Движение мягких тканей лица с челюстью** — последним, после
  проигрывания движений, только для показа пациенту.

## Принципы

- **Назначение.** Отдельная некоммерческая программа для Windows: «как IPS
  CaseDesigner, но лучше». Кейс пациента собирается в ней, затем переносится
  в пространство exocad, где моделируют ортопедические конструкции.
- **Данные.** Только полночерепные КТ.
- **Открытые модели и знания.** Используем по максимуму, если они не
  противоречат концепции, всегда с лицензией и авторством. Продукт
  некоммерческий, поэтому компоненты с некоммерческой лицензией можно
  использовать полностью. Код и веса OdentAI не используем: у них нет
  лицензии. Интерфейс свой.
- **exocad.** Подключение только официальными средствами и форматами:
  без вмешательства в код и файлы программы.
- **Пациенты.** Имена пациентов не выводятся, не сохраняются и не попадают в
  репозиторий. Реальные кейсы хранятся вне репозитория.
- **Интерфейс.** Спокойный, без лишних кнопок и без вида «сделано ИИ», по
  образцу профильных программ. Всё, что можно показать наглядно, показывается.

## Что должно получиться

### 1. КТ и сегментация
- Набор структур как у OdentAI: зубы по отдельности, челюсти, каналы, пазухи,
  череп, полость носа, нёбо, дыхательные пути.
- Открытые веса, дообучение по минимуму.
- КТ из папки DICOM, архива или файла; если серий несколько, выбор серии.

### 2. Сканы на КТ
- Интраоральные сканы и сканы гипсовых моделей с цоколем.
- Совмещение только по коронкам. Десна и нёбо на скане, корни на КТ не
  участвуют.
- Ручная коррекция как в RealGUIDE: манипулятор на срезах, контуры по
  отклонению, отмена и возврат.
- Программа учится на итоговых положениях, которые выставил пользователь, и с
  каждым кейсом совмещает лучше.
- Предупреждение о перекосе дуги, когда часть скана не ложится на КТ.

### 3. Прикус и единые координаты
- Прикус сканов приоритетнее прикуса на КТ.
- Два режима:
  - по умолчанию структуры нижней челюсти идут вслед за нижним сканом в
    прикус сканов;
  - второй режим — статичное наложение на КТ.
- Автоориентация КТ, сканов и сегментов в координатах exocad.
- Экспорт всех 3D-объектов в единых координатах: сканера (exocad) или КТ.

### 4. Ориентиры, плоскости, цефалометрия
- Цефалометрические точки: нейросеть ставит их сама, врач правит на срезах.
- Стандартные анализы, например Steiner и Ricketts.
- Плоскости: Франкфуртская, HIP, Кампера, окклюзионная; шарнирная ось через
  мыщелки.
- Выгрузка в координатах виртуальных артикуляторов.

### 5. Эстетика
- Фото анфас в привычном для пациента положении головы, профиль — по
  желанию.
- Люди асимметричны: эстетический горизонт и средняя линия не совпадают с
  костными ориентирами, а зрачковая линия ненадёжна.
- Сканы и модели выгружаются и в функциональной, и в эстетической системе;
  расхождение показывается в градусах и мм.
- 3D-скан лица, если есть:
  - сначала статичный, совмещённый с кожей на КТ;
  - затем несколько выражений (покой, улыбка, открытый рот);
  - движение мягких тканей вместе с челюстью — в последнюю очередь, только
    для показа пациенту.

### 6. Виртуальный артикулятор
- Свой артикулятор, который «гипсует» пациента.
- Галочка «По эстетической плоскости»: включена — модели стоят по
  эстетической плоскости, выключена — по функциональной (Франкфурт, HIP,
  Кампер). Галочка меняет только положение моделей.
- Динамика всегда по мыщелкам пациента с КТ. Справа и слева они могут стоять
  на разной высоте и глубине; ось вращения проходит через оба реальных
  мыщелка. Движение от галочки не меняется.
- Углы суставного пути из реальных данных пациента:
  - бугорок и мыщелки по КТ при правильном монтаже;
  - геометрия и стёртость зубов по сканам;
  - записи движений.
- Все распространённые артикуляторы и вариаторы, включая Gamma.

### 7. Движения, как в Bite-Finder, но не хуже
- Исправление прикуса, как в Bite-Finder, одной кнопкой:
  - нижняя челюсть ищет положение максимального фиссурно-бугоркового
    контакта по всем шести степеням свободы: вверх-вниз, вперёд-назад, в
    стороны и повороты;
  - зубы не проникают друг в друга, контакты распределены равномерно;
  - исправляется и провален или не сомкнут прикус, и сдвиг вперёд-назад или
    вбок;
  - если скана прикуса нет, прикус находится по одним сканам челюстей;
  - преимущество перед Bite-Finder — полночерепное КТ: мыщелки должны
    остаться в суставных ямках, а соотношение челюстей на КТ подсказывает,
    какой из похожих вариантов прикуса верный;
  - неверный прикус программа замечает сама и показывает, на сколько он
    сдвинут: мм по резцам и молярам, градусы, контакты по зубам до и после;
  - пользователь принимает или отменяет исправление, по умолчанию остаётся
    прикус со сканера;
  - проверка точности на кейсах из архива: верный прикус сбивается на
    известную величину, программа должна его вернуть.
- Генерация движений без записи: протрузия, латеротрузии, открывание.
  Движение идёт либо по оси мыщелков, либо по сгенерированным путям.
- Для скольжения по зубам подходят только сканы челюстей. Модели зубов из КТ
  в динамике не участвуют.
- Настоящие записи: P-ART, Zebris, Modjaw, CADIAX и другие системы. Их можно
  сравнить с генерацией или использовать вместо неё.
- Анимация и карта контактов: что ведёт, где суперконтакты. FGP — в STL.
- Выгрузка движения, сгенерированного или записанного, в файл, который
  открывает exocad (Jaw Motion Import).

### 8. Связь с exocad
- Автозагрузка кейса в exocad: правильные имена объектов и файлов, чтобы
  exocad сам всё подтягивал, без указания объектов вручную.
- Монтаж в виртуальный артикулятор exocad: мыщелки на шарнирах, модели на
  своих местах.
- Свой виртуальный артикулятор для exocad под кейсы из программы:
  - модели стоят по эстетической плоскости, а динамика идёт по
    артикуляционной оси пациента;
  - шарнир каждого мыщелка ставится на мыщелок пациента отдельно во всех трёх
    плоскостях: выше-ниже, вперёд-назад, внутрь-наружу; справа и слева
    по-разному;
  - суставные пути — с углами пациента (сагиттальный, Беннетта, боковой
    сдвиг), перенесёнными в эстетический монтаж без искажения.
- Зачем: у стандартных артикуляторов exocad шарниры стоят на фиксированных
  местах и симметрично. После монтажа по эстетической плоскости мыщелки
  пациента оказываются не на шарнирах, и движение в exocad уже не
  пациентово.
- Делается только официальными средствами, если exocad позволяет добавлять
  свои артикуляторы. Если не позволяет:
  - точную динамику даёт файл движения из раздела 7;
  - для стандартного артикулятора exocad программа подбирает лучшие
    настройки и показывает, на сколько мм его движение расходится с
    пациентом.
- Устройство виртуального пространства и артикуляторов exocad изучаем, когда
  будет доступ к программе.

## Отдельно от программы

- **Соты.** Генератор сот на выбранных гранях модели, с выделением как в
  Materialise Magics. Код удалён из этой папки по вашей просьбе и остался в
  истории git. Встроить выделение граней в окно exocad можно только через
  официальный SDK по партнёрской программе exocad. Без него — своё окно,
  которое открывается, когда exocad сохраняет модель в папку проекта.

- Реальные кейсы: КТ + сканы, КТ + сканы + запись движений, фото. Данные

- Локальная сессия на ПК для группы Б: релиз моделей, сборка, реальные кейсы.
